# Windows UI 对齐验证

代码以 macOS ContentView、AppTheme 和 MonitorMenu 为布局及配色基准。Windows 保留原生窗口、WPF 控件和 UAC，新增独立设置、首次配置和托盘监控面板。macOS 源码及 Rust 网络算法未改动。

## 环境与结果

- 远程机器：alex@192.168.100.123，Windows 11；独立工作目录 `C:\Users\alex\gptProxy-ui-parity`。
- 本机 Windows 目标交叉编译通过，应用和服务零警告。
- 远程现有验证：38 项 Rust、19 项 C#、10 个 SOCKS/TLS 场景、5 个 DNS 场景通过，应用及服务自包含发布成功。
- 新增 WPF 检查通过：旧主题数字迁移、稳定主题 ID 优先级、未知主题回退；五种主题的主窗口空闲/长文本监控、设置、首次配置及托盘，共 25 张图；另有 150%/200% 渲染图；托盘更新不移动操作按钮，忙碌期间冲突控件禁用。
- 直接检查渲染图片后调整主窗口行距，默认尺寸下主要操作可见；长节点名称省略并提供完整提示。
- 渲染检查发现并修复“主窗口从未显示时无法打开设置”的窗口 Owner 错误，覆盖登录仅驻留托盘的入口。

完整输出：远程 `windows-ui-verification.log`；最终渲染证据位于 `build/windows-ui-visuals`。便携包位于远程 `dist`，本机副本位于 `build/ui-parity`。

## 验证边界

本轮没有改变远程桌面的实际显示缩放，也没有通过交互桌面逐项点击 UAC、启用保护或重启 ChatGPT。高 DPI 证据来自 WPF 渲染；网络证据来自既有自动化回归，不能当作本轮完整保护生命周期实测。远程原正式版本、ProxyBridge 桌面实例、用户设置和网络配置保持原样。
