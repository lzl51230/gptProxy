# CLI 日志积压修复验证

版本：ChatGPT Proxy 2.3.3（构建号 11）。环境：Apple Silicon、macOS 26.6、Apple Swift 6.3.3。

## 原因与复现

参考会话 `01a1ab3d-533b-75b1-8def-73fa2200500b` 和 HerdrContinue 提交 `b086ec8`：原工程的根因是 Avalonia macOS 无障碍引用生命周期问题，UI 快照积压及日志控件重建放大内存增长。本工程使用 SwiftUI，没有该 Avalonia 原生依赖。

本工程确认的同类问题在 `ProxyBridgeCLIController`：每次管道可读回调都创建一个捕获原始 `Data` 的 MainActor 任务。单行缓冲的 64 KiB 限制只在任务执行后生效，不能限制主线程尚未消费的日志数据。

以真实控制器连接模拟 CLI，在主线程暂不消费时输出 64 MiB、每行 4 KiB 的日志：原实现两次增加约 72 MiB RSS；固化后的回归测试在修复前失败，实际使用的堆内存增加 73,861,728 字节，RSS 增加 74,219,520 字节。另一个分轮复现确认，消费完成后堆内存从约 18 MiB 回到约 0.23 MiB。这条路径属于无界排队，不是已消费对象仍被持久引用。

## 修改与自动化验证

- 用串行后台队列和非阻塞、固定大小管道读取处理日志；解析和写盘同步执行，慢消费者通过管道背压限制生产速度。
- stdout/stderr 分别最多保留 64 KiB 未完成行。完整和分片超长行均报错，并丢弃到下一换行；支持跨块 UTF-8 和 EOF 尾行。
- 仅向主线程投递累计状态，最多一个待执行通知。通知不携带原始日志，停止后丢弃待处理状态；取消确认后关闭读取描述符和日志句柄。
- 运行中收到 CLI 错误会撤销就绪状态。保留现有 5 MB 日志轮转和公共启动、停止接口。
- 全部 144 项测试通过，包含 64 MiB 真实管道回归、累计状态合并、超长行、双输出流、EOF、日志失败、反复启停、持续输出期间取消及运行后错误。
- `scripts/verify.sh` 通过：arm64/x86_64 Release 构建、应用和辅助服务签名、配置隔离、ZIP 内容与架构校验。
- Thread Sanitizer 下相关 17 项测试通过，未报告数据竞争：`swift test --scratch-path .build/tsan-memory --sanitize=thread --filter 'CLIOutput|ProxyBridgeCLIControllerTests'`。

## 持续压力测试

使用 `scripts/qa-cli-memory.py` 链接本工程实际编译对象，只运行模拟子进程，不访问 Clash 或改变系统网络。每轮向 stdout/stderr 合计输出 64 MiB，暂停主线程消费，等待日志排空，再停止子进程。每轮记录实际使用的堆内存、RSS、真实打开的文件描述符数和子进程清理结果。

```sh
python3 scripts/qa-cli-memory.py --seconds 1800 --output dist/memory-soak-final-2026-11-06
```

完整测试通过：连续 1,801.36 秒，176 轮，累计输出 11 GiB。所有轮次均完成日志排空和子进程退出；停止后的真实文件描述符数始终为 4。每轮主线程暂停场景中的最大采样 RSS 增量为 278,528 字节（272 KiB），低于 16 MiB 验收上限。

预热后的实际使用堆内存由 222,688 字节变为 225,120 字节，净增 2,432 字节；最后一轮停止后 RSS 为约 10.34 MiB。这里分别记录实际使用的堆内存和 RSS，不把分配器保留的驻留页当作仍存活的日志对象。原始样本、汇总和源文件 SHA-256 保存于上述目录；安装前核对源码哈希未改变。

早期短时试跑验证了内存边界，但文件描述符计数最初使用了系统预估缓冲容量；已改为实际返回条目数并重新开始完整测试，早期试跑不计入最终长期验收。
