# ChatGPT Proxy

适用于 macOS 14 及以上版本的启动器，可将 OpenAI 桌面应用的流量转发到用户指定的本地 SOCKS5 代理。默认上游代理端口为 `7890`。

启动器不会修改 macOS 系统代理设置，而是在 `127.0.0.1:17890` 运行本地 TCP 中继。内置的 ProxyBridge 配置会匹配 `com.openai.*`、旧版 `com.openai.chat`、`ChatGPT`、`codex`、`codex-code-mode-host`、`codex_chronicle*` 和 `org.sparkle-project.*`，并将匹配的流量转发到中继。启动器托管 ProxyBridge 4.1.1 CLI，通过标准输入加载内置规则，确认规则完整生效后才允许启动 GPT。无需打开 ProxyBridge 窗口或修改其偏好文件。启动 GPT 时同时将其 Electron HTTP(S)/WebSocket 代理指向内部 SOCKS5 中继，让域名在代理端解析，避免本地 DNS 无回包导致界面离线；本机和 192.168.*.* 仍绕过该代理。首次运行需在 macOS 批准网络扩展；其他 CLI 实例须先自行停止。关闭窗口后继续驻留，正常退出时先停止 CLI 再关闭中继。

启动器还会为 ChatGPT 及其原生 Codex 子进程设置大小写 `HTTP_PROXY`、`HTTPS_PROXY` 和 `ALL_PROXY`，统一指向 `socks5h://127.0.0.1:17890`，让原生账户、工作区路由和模型请求也由代理端解析域名，避免 `workspace routing discovery timed out`。大小写 `NO_PROXY` 统一保留本机和 `192.168.0.0/16` 直连，其他继承的环境变量保留。更新启动器后，需通过它重新启动 ChatGPT 才会应用这些设置。

启动器要求使用支持 Codex 的新版 ChatGPT 桌面客户端；检测到旧版 `com.openai.chat` 客户端时，会提示更新。

规则也会代理其他路径下的同名 Codex 程序，以及其他应用的 Sparkle 更新器。`localhost`、`127.0.0.1`、`::1` 和 `192.168.*.*` 的 TCP 连接保留直连；其他原生 IPv6 TCP 连接被阻断，其余匹配的 TCP/UDP 连接通过代理。通用工具进程（如 curl、git、Python）不在匹配列表中。

“打开 .codex”按钮可打开当前用户的 Codex 配置目录；目录不存在时会自动创建。

## 构建

需要 Xcode 16 或更高版本。

```sh
make verify
```

构建后的应用位于 `build/ChatGPT Proxy.app`，分发文件为 `dist/ChatGPT-Proxy-2.3.3-Universal.zip`。ZIP 只包含 ChatGPT Proxy（含 DNS 辅助服务）；解压后将应用放入 `/Applications`。不包含 ChatGPT、ProxyBridge 或它们的安装包。

应用检测 ProxyBridge 是否安装完整且版本为 4.1.1；不满足时，状态行显示“修复”。点击后通过设置中的本地 SOCKS5 代理在线下载固定版本官方安装包，校验 SHA-256 与签名团队，再通过 macOS 命令行安装器安装。管理员认证由系统完成；成功后自动重新检测并启用代理，不自动打开或重启 GPT。下载失败请检查本地代理设置，可重试；没有直连回退。版本正确但扩展待授权时，使用网络扩展设置入口完成授权。

本项目未配置 Apple Developer ID 证书，启动器采用临时签名。在其他 Mac 上首次打开时，可能需要在“隐私与安全性”中允许运行。下载安装的 ProxyBridge 保留官方签名。历史统一安装包移至 `build/legacy-distributions`。

## 系统 DNS 保护

点击“启动 ChatGPT”时先启用 DNS / IPv4 保护，也可在主窗口单独启用。单独启用时自动重启已经打开的 GPT，使旧连接采用新策略；GPT 未运行时不额外启动。首次启用通过 macOS 管理员认证安装 root 辅助服务；无需自定义 Network Extension 签名。登录驻留不自动申请管理员认证。2.3.1 使用辅助服务协议 2，首次启用会先恢复旧事务再升级服务。

如果 GPT 未在正常退出请求后 15 秒内结束，或重新打开失败，会恢复网络设置并显示错误，不强制终止 GPT。等待过程中可取消。此时请手动退出 GPT 后重试。

要求官方 ProxyBridge 4.1.1，内置配置关闭其 DNS 扩展，避免它接管并终止 TCP DNS 连接。TCP/UDP 流量规则保留；域名解析由本项目和 Clash 负责。4.1.0 用户需通过“修复”升级。

仅支持匹配到唯一 Clash Party 实例、全局模式、实际代理节点且 TUN 关闭的情况。普通系统解析经 `127.0.0.1/::1:53` 转入 Clash 的 `127.0.0.1:17853`，再通过当前 `GLOBAL` 节点请求 Cloudflare 和 Google DoH。GPT 通过 SOCKS5 提交的域名也使用该配置。临时采用 `redir-host` 返回真实地址，不改订阅文件。节点自身的 `default-nameserver` 与 `proxy-server-nameserver` 必须使用独立加密解析；引导服务器必须是 IPv4 地址，不接受 IPv6 字面地址，避免解析依赖尚未建立的代理。

保护期间，当前共用 Clash 实例的顶层 `ipv6` 和 `dns.ipv6` 均临时关闭，普通节点及 provider 覆盖使用 `ip-version: ipv4`。同时使用该实例的其他应用也受影响，启用时会断开现有 Clash 连接一次，让它们按新策略重建。IPv4 解析和 AAAA 空响应检查通过，并完成所需 GPT 重启后，窗口才显示保护成功。节点无可用 IPv4 或启用失败时恢复原设置，不回退 IPv6 或直连。

此策略限制本机到节点的地址族，不控制远端节点到网站的地址族。GPT 原生 IPv6 TCP 被阻断；UDP 全部经代理，节点连接使用 IPv4。ProxyBridge 4.1.1 对 UDP 只按进程匹配，不能用 IPv6 `BOTH + BLOCK` 规则，否则会误封 IPv4 UDP 和语音流量。macOS 的 IPv6 及 `::1` 本地 DNS 服务保留。

保护期间，所有已启用物理网络服务的 DNS 指向本地服务；PF 专用 anchor 阻断非环回接口上的 IPv4/IPv6 TCP/UDP 53，并精确清理既有 DNS 状态。其他 PF 规则、mDNS、其他端口保持原样。应用自带 DoH/DoT 不属于明文 53 阻断范围；检测到 VPN 或其他系统 DNS 覆盖时停止保护。

辅助服务独立于窗口进程检查链路、IPv4 策略、网络服务和节点变化。连续两次检查失败、Clash 配置重新加载、启动器失去响应或退出时，自动还原 DNS、Clash 配置和自身 PF 规则；恢复时保留用户随后手动修改的 DNS、节点和模式，并还原本次临时覆盖的 IPv6 开关。用户主动开启 IPv6 或加载新配置时保留其选择。主窗口显示“保护已关闭”，不自动重新开启。恢复后系统可以使用原 DNS 和 IPv6，届时不保证受保护。

恢复记录位于 `/Library/Application Support/ChatGPT Proxy DNS/recovery.json`，仅 root 可读，可能包含原 Clash 配置。正常恢复成功后删除；崩溃或重启后优先恢复未完成的事务。辅助服务只接受安装用户或 root 的固定控制命令，不记录查询域名及订阅凭据。

应用无法打开时，可在终端恢复：

```sh
sudo /Library/PrivilegedHelperTools/local.alex.chatgpt-proxy.dns --restore
```

卸载辅助服务（先恢复原配置，再删除 LaunchDaemon 和辅助程序）：

```sh
sudo /Library/PrivilegedHelperTools/local.alex.chatgpt-proxy.dns --uninstall
```

PF 状态清理目前限定已审核的 Darwin 23–25（macOS 14、15、26）ABI；遇到其他系统版本拒绝启用，避免误操作防火墙。

2026-11-05 在 macOS 26.6、Clash v1.19.24 和 ProxyBridge 4.1.1 上完成 2.3.0 本机联调：IPv4/IPv6 环回的 TCP/UDP DNS 均可用，外部 TCP/UDP 53 查询被阻断，Clash 连接链确认两家 DoH 均经当前 GLOBAL 节点。一键恢复及正常退出均还原全部网络服务 DNS；强制终止启动器后，独立服务约 4 秒内恢复。每次恢复后均核对系统解析器、各服务 DNS 与原始 Clash 文件，结果与修改前一致。自动化测试共 117 项通过，包含后台定时回调与恢复失败注入测试。其他系统版本仍需各自完成联调验收。

同日完成 2.3.1 联调：A 返回 IPv4，AAAA 返回空结果；可控 IPv6 端点允许普通进程访问，匹配 GPT 的测试进程被阻断；IPv4 UDP 经 GLOBAL 节点正常返回，节点的非环回连接均使用 IPv4。切换节点后约 6 秒内 DoH 跟随新节点。手动开启 Clash IPv6 后约 9 秒自动停止保护；强制终止启动器后约 4 秒恢复原 IPv6、DNS 及配置。正常退出及重启失败后的回滚均验证通过；首次 GPT 重启测试未等主界面完全加载，后续确认 3 秒退出期限也不足，因此当时未验证成功重启。共 130 项测试及双架构、签名和 ZIP 检查通过，临时 IPv6 测试地址和抓包进程已清理。

2.3.2 补齐真实 GPT 自动重启成功的本机验收：先由用户确认 GPT 主界面可正常操作，并让旧进程稳定运行超过一分钟，再重新启用保护。旧 GPT 正常退出，新进程携带 SOCKS 代理参数启动，启动器显示保护成功，用户再次确认重启后的主界面完全加载且可正常操作；IPv4 开关、A 解析和 AAAA 空响应复核通过。正常退出等待上限从 3 秒延长至 15 秒，等待中取消或超时仍会回滚。新增慢退出、超时回滚和取消回归测试，共 134 项测试及双架构、签名和 ZIP 检查通过。


启动前检测通过配置的本地 SOCKS5 代理检查 UDP Associate，并向 https://chatgpt.com/backend-api/codex/models 发送一次无凭据请求；HTTP 401 表示接口可达且要求认证。不再查询出口地区或按 CN 地区拦截。检测仅验证网络可达及连接保持情况，不验证账号、额度或模型会话。

后台监控与自动切换：
- 打开应用即监控，关闭窗口后继续驻留菜单栏；菜单栏可暂停、恢复或退出，暂停状态会保存。
- 持续复用一条 TCP/TLS 连接，每 2 秒向上述 Codex 地址发送无凭据 HTTP/1.1 心跳，要求 HTTP 401。初次建链最多等待 10 秒，之后连续 10 秒无有效响应、连接关闭、TLS 错误或异常状态均判为失败；不使用登录凭据，不跟随重定向，保留 TLS 证书校验，由代理端解析域名。
- 同一连接从首个有效心跳起考核 60 秒。未满 60 秒断线计一次，1 秒后重连；连续两次才启动节点恢复。有效心跳确认已满 60 秒即清零失败计数，继续维持原连接。底层重连重新计时；维持阶段不因延迟超过 800 ms 切换。
- 仅支持 Clash Party 全局模式，恢复始终限制在同一订阅内。先测试当前地区，再按已勾选备用地区从上到下尝试；每地区最多并发测速 4 个节点，每轮每节点只测一次。使用同一 Codex 地址、预期状态 401，测速期限 10 秒；仅延迟大于 0 且不超过 800 ms 的候选入选，并按延迟、节点名排序。
- 首轮跳过触发恢复的节点。按排名临时选中候选，确认实际选择并清理上一节点的旧 GLOBAL 连接，再用全新连接验收。候选保持满 10 秒且收到有效心跳才接受；中途失败继续尝试下一节点或地区。验收通过的同一连接继续进入 60 秒考核，已验证的 10 秒计入时长。
- 两次节点选择写入间隔至少 5 秒。全部候选失败后保留控制器实际选择，按 2、4、8、16、30 秒退避重试，之后保持 30 秒；后续轮允许重新评估失败节点。
- 设置可勾选备用地区并调整优先级，自动保存；新增地区默认不勾选，暂时缺失的地区保留并跳过。手动换节点、订阅或配置变化、改端口、暂停及系统唤醒时关闭旧观察并重新计时；健康时不会主动回切。
- 无法确认节点来源或地区时不切换；规则／直连模式或控制接口不可用时仍监测 Codex。无需另开控制端口。
- 主窗口和菜单栏显示心跳延迟、连接已验证时长、失败计数、候选验收进度和上次断线原因；恢复失败显示下次重试等待时间。
- 监控日志位于 ~/Library/Logs/ChatGPT Proxy/monitor.jsonl，超过 5MB 自动轮转。正常退出等待监控连接释放。


主窗口齿轮、菜单栏“设置…”或 ⌘, 可打开设置窗口。“开机自启动”使用系统登录项注册，开启后在“系统设置 → 通用 → 登录项与扩展 → 登录时打开”中显示 ChatGPT Proxy。登录启动仅驻留菜单栏；手动启动显示主窗口。首次安装默认不注册，状态以系统实际设置为准。

设置中的“外观 → 颜色主题”支持跟随系统（默认），以及参考 [VS Code 内置主题](https://github.com/microsoft/vscode/tree/main/extensions) 的 Dark Modern、Light Modern、Monokai 和 Solarized Dark 配色。主题立即应用到主窗口、设置窗口和首次配置面板，并自动保存；选择“跟随系统”可恢复 macOS 外观。

ProxyBridge 活动日志位于 `~/Library/Logs/ChatGPT Proxy/proxybridge.log`，达到 5 MB 轮转。主窗口可查看日志、取消下载或启用；修复入口通过命令行安装器及 macOS 原生管理员认证完成。

2.3.3 将 CLI 日志读取、解析和写盘放在串行后台队列，主线程只接收合并后的状态。每个输出流的单行缓冲限制为 64 KiB；主线程繁忙或磁盘较慢时，不再为每块日志创建携带原始数据的任务。运行中收到 CLI 错误会撤销就绪状态。

隔离内存压力测试使用模拟 CLI，每轮通过 stdout/stderr 输出 64 MiB 日志并重启子进程，记录主线程暂停期间的堆内存、RSS、文件描述符及进程清理结果，不更改代理或 DNS：

```sh
python3 scripts/qa-cli-memory.py --seconds 1800 --output dist/memory-soak
```

输出目录须不存在；结果写入 `summary.json` 和 `samples.jsonl`。短时间冒烟可使用 `--seconds 20`。

2.3.3 的复现、30 分钟压力测试和本机更新结果见[内存修复验证记录](docs/validation-memory-2026-11-06.md)。
